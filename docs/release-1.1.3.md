# TS Overlay 1.1.3

Исправление подсветки «говорит» для человека с выключенным микрофоном.

## Причина

TeamSpeak отдаёт не только статусы `0` (молчит) и `1` (говорит), но и `2` —
«talking while disabled»: клиент издаёт звук, но микрофон у него выключен.
Оверлей считал любой ненулевой статус говорящим и подсвечивал такого человека зелёным.

## Что исправлено

- Говорящим считается только `status == 1` (TS3 и TS6).
- Подсветка дополнительно подавляется, если у клиента `inputMuted`, `inputDeactivated`
  или серверный `isMuted`: выключенный микрофон важнее статуса.
- Серверный мьют (`isMuted`) теперь учитывается и в TS3 (`client_is_muted`), и в TS6.
- При перемещении клиента по каналам больше не теряются флаги микрофона: частичные
  свойства из `clientMoved`/`clientUpdated` сливаются с уже известным состоянием.
- Инициалы аватара для ников без пробелов — в верхнем регистре.

## Установка и обновление

- С 1.1.0–1.1.2: трей → «Проверить обновления» → 1.1.3.
- Или вручную: `TsOverlay-1.1.3-Setup.msi` (per-user, без UAC) из этого релиза.
- Настройки и ключи API сохраняются.

## Если человек всё ещё подсвечивается

Пришлите `%APPDATA%\TsOverlay\probe.log`, снятый в момент, когда он «говорит» с выключенным
микрофоном:

```powershell
TsOverlay.exe --probe ts6 --probe-seconds 20
```

В логе видно `status=` и флаги `mic-off`/`deaf`. Если у клиента статус `1` и `inputMuted=false`,
значит сам клиент не сообщает о мьюте через Remote Apps — тогда нужен резервный источник
(ServerQuery с правами на сервере).
