# TS Overlay 1.2.5

Исправлена задержка обновлений в TS6: переключение серверов, мьют/анмьют и выход людей
из канала больше не ждут полного переподключения.

## Причина

В TS6 может быть несколько серверных подключений (вкладок). При авторизации приходил список
`[1,3]`, и код выбирал первое подключение, где встречается свой `clientId` — `1`. А события
клиента (мьют, обновления, уход из канала) приходили с `connectionId=3`, то есть от активного
подключения.

Дальше:

- любое событие с другим `connectionId` считалось «переключили сервер» → полный реконнект;
- остальные события просто отбрасывались;
- после реконнекта авторизация снова выбирала `1`, и цикл повторялся.

Отсюда «мут ставится сразу, снимается через несколько секунд» и «кто вышел — видно не сразу»:
изменения применялись только после очередной полной синхронизации.

## Что исправлено

- **Активное подключение определяется по `clientSelfPropertyUpdated` с `flag="inputHardware"`** —
  это официальный признак смены активного сервера в Remote Apps. Код запоминает его
  (`_preferredConnectionId`) и при авторизации выбирает именно это подключение.
- События неактивных подключений больше не вызывают реконнект — они просто игнорируются.
- При переключении на другой сервер и обратно выполняется **один** ресинк на переключение,
  после чего события текущего сервера применяются сразу.
- Добавлена обработка `clientLeft` / `clientDisconnected` (в т.ч. в `proto`-обёртке) — уход
  человека применяется по событию, а не после переподключения.
- В лог пишется список подключений и выбранное: `TS6: подключения [1,3], выбрано 3`.

## Сценарии

- **Переключился на другой сервер** — приходит `inputHardware`, один ресинк, дальше обновления
  идут в реальном времени.
- **Вернулся обратно** — то же самое, один ресинк.
- **Сервер упал / выкинуло** — `connectStatus=0` очищает состояние, переподключение поднимает
  активное подключение.
- **Мьют/анмьют** — применяется сразу, без ожидания реконнекта.
